## 결정

- **린트는 기준선 방식.** 기존 오류 11개(대부분 `react-hooks/set-state-in-effect`)를 고치면 effect의 동작이 바뀔 수 있어 손대지 않았다. 늘 실패하는 검사는 무시되므로 `tool/lint-baseline.json`에 (파일, 규칙)별 개수를 적고 늘어난 것만 실패로 본다.
- **테스트는 순수 함수만.** 컴포넌트·API·Supabase는 mock이 커져 이번에는 넣지 않았다. `market.ts`(`next/cache`), `naver.ts`의 `fetchNaverJson`(네트워크), `post-reactions.ts`(Supabase)는 건너뛰었다.
- **vitest 4.x.** 5.x는 `@types/node` 22 이상을 요구해 이 저장소(`^20`)에서 설치가 실패했다.
- **기호 검사에서 '옮겨졌다' 판정은 뺐다.** holdem은 "쓰기만 하고 선언은 다른 파일"을 실패로 보지만 TypeScript는 import해 쓰는 일이 흔해 거짓 경보가 난다. 그 파일에 낱말이 없거나 import 줄에만 있을 때만 실패다.
- **800줄·24KB 기준은 holdem 것을 그대로.** 지금 걸리는 파일은 없다(가장 긴 `CandleChart.tsx` 743줄).
- **사람용 설명서(`docs/README.md`, `01`~`06`)는 고치지 않았다.** 이 세션 전부터 커밋되지 않은 채 있던 다른 작업이다(수정된 `README.md`도 같다). 색인의 '문서' 표에 2026-09-23 기준이라는 것과 지금 코드와 다른 곳을 적었다.

## 덧붙임: 권한 마이그레이션과 커밋

같은 날, 위 보고를 본 사용자가 세 가지 물음(커밋 안 된 설명서를 같이 올릴지, 권한 문제 둘을 새 마이그레이션으로 막을지, 작업이 끝나면 묻지 않고 커밋·push할지)에 "응 그렇게 해", 이어서 "묻지 말고 푸시하고"라고 했다.

- **`supabase/migrations/20261122000003_tighten_memo_and_profile_rls.sql`**: `chart_memos`의 정책 넷을 본인 행만(`auth.uid() = user_id`)으로 바꾸고 `chart_memos_stock_date_unique`를 지웠다. `profiles`는 `anon`·`authenticated`의 테이블 단위 UPDATE를 거두고 `authenticated`에 `nickname`·`onboarded` 열만 허용했다.
- 근거로 본 코드: 메모는 로그인한 사용자만 쓰고 `eq('user_id', userId)`로 본인 것만 읽으며 upsert의 `onConflict`는 `user_id,stock_code,date`다(`src/components/stock/StockChartSection.tsx`). 프로필을 고치는 곳은 `/auth/setup`의 `update({ nickname, onboarded })` 하나다.
- 하지 않은 것: `chart_memos.user_id`의 NOT NULL과 FK 되돌리기(프로토타입 때의 NULL 행이 운영 DB에 있으면 실패한다. 행은 확인 못 함). NULL 행은 지우지 않았고 이제 아무에게도 보이지 않는다.
- 확인 못 한 것: 로그인한 실제 사용자로 메모 저장·삭제와 닉네임 설정이 되는지(이 세션은 로그인할 수 없다). 마이그레이션 워크플로의 적용 결과와 Vercel 배포 상태는 push 뒤에 확인해 사용자에게 보고한다(이 기록을 쓴 때는 push 전이다).
- 사람용 설명서(`README.md` 수정, `docs/README.md`와 `01`~`06`)는 내용을 고치지 않고 따로 커밋해 같이 올렸다.
- '묻지 않고 커밋·push'를 [저장소 규칙](../../CLAUDE.md)과 [결정과 일하는 방식](../decisions.md)에 적었다.
