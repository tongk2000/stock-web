# 결정과 일하는 방식

사용자가 말로 정한 것, 운영하며 알게 된 것, 아직 정하지 않은 것을 모은다. 대화와 Claude 메모리는 다음 세션에 넘어가지 않으니 여기에 날짜와 사용자 말로 적는다. 매번 걸리는 규칙만 [저장소 규칙](../CLAUDE.md)에 요약돼 있고, 이유와 나머지는 여기가 정본이다.

관련: [프로젝트 색인](INDEX.md), [작업 기록 색인](history/README.md), [문서 안내](CLAUDE.md).

holdem에서 옮기며 사용자에게 따로 확인받지 않은 것(에이전트가 본보기대로 적었다. 맞지 않으면 고친다):

- 색인은 작업마다 고치고, 판단이 드는 정리는 정리 세션(`/stock-tidy`)에서 따로 한다(holdem에서 2026-11-19 사용자: "둘 다 하자").
- 한 파일이 800줄쯤을 넘으면 관심사별로 나눈다(holdem의 기준. 지금 가장 긴 파일은 `src/components/chart/CandleChart.tsx` 743줄).
- 폴더 안내 24KB 한도.

## 계획

### 토론 도배 방지

메모 단계다(2026-05-04 커밋 `07bbb36`). 옛 `AGENTS.md`에 있던 메모를 옮겼다. 구현 여부는 [색인의 '지켜야 할 규칙'](INDEX.md#지켜야-할-규칙)에 적는다.

- 글/댓글 재등록 텀은 클라이언트와 서버 양쪽에서 검증하되, 최종 차단은 서버 또는 Supabase RPC/DB 레이어에서 강제한다.
- 초기 정책은 단순하게 시작한다: 글은 `user_id`당 약 60초, 댓글은 `user_id`당 약 10~15초 쿨다운을 기준으로 검토한다.
- 동일 본문 반복 차단은 "유사도"가 아니라 "정규화 후 완전 동일"만 우선 막는다.
  - 정규화 기준 예: `trim()`, 소문자 변환, 연속 공백을 단일 공백으로 치환.
  - 저장은 원문 중복보다 `content_hash` 컬럼을 우선 검토한다.
  - 차단 범위는 글의 경우 같은 `room_id`, 댓글의 경우 같은 `post_id` 안에서 최근 5분 내 같은 `user_id` + 같은 `content_hash`를 기준으로 한다.
- 시간 창이 있는 중복 차단은 unique constraint보다 insert 직전 서버/RPC 조회로 처리하는 편이 단순하다.
- 클라이언트의 버튼 비활성화/남은 시간 표시는 UX 보조일 뿐, 보안 경계로 취급하지 않는다.
