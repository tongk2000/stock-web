# 정리 세션

기능을 만드는 작업 중에는 하지 않는 정리를 한 번에 한다. **동작과 화면은 바꾸지 않는다.** 동작·DB 스키마·API 응답이 바뀌는 것은 고치지 않고 목록으로 사용자에게 묻는다. 인자 `$ARGUMENTS`가 `web`(`src`, `test`)·`collector`(`stock-collector`, `.github/workflows`)·`docs`면 그쪽만 한다.

규칙은 [저장소 규칙](../../../CLAUDE.md)이 먼저다(서브에이전트 모델, 검사, 커밋과 push). 지난 정리는 [작업 기록 색인](../../../docs/history/README.md)의 '문서·규칙·도구' 표에 있다.

## 1. 무엇을 할지 찾는다

1. `python3 docs/check-index.py`. 실패는 먼저 고친다. `NOTE:` 줄이 할 일이다: 800줄을 넘은 소스 파일, 한도(24KB)에 가까운 폴더 안내.
2. 줄 수가 600을 넘어 곧 걸릴 파일을 본다(고칠 일이 많은 파일부터 고른다).
   `git ls-files 'src/**/*.ts' 'src/**/*.tsx' 'stock-collector/*.py' | xargs wc -l | sort -n | tail -10`
3. `python3 tool/lint-check.py`. 기준선(`tool/lint-baseline.json`)의 기존 오류 가운데 동작을 바꾸지 않고 고칠 수 있는 것을 고른다. effect 안의 `setState`처럼 고치면 동작이 바뀔 수 있는 것은 '묻는 목록'으로 뺀다.
4. 정리할 곳을 읽기만 하는 조사로 찾는다(서브에이전트, Sonnet). 찾는 것: 부르는 곳이 없는 코드, 코드와 다른 주석, 두 군데 이상 같은 로직, 폴더 안내의 '어디를 볼까'·'지킬 것'이 지금 코드와 맞는지, 색인(`docs/INDEX.md`)의 줄이 맞는지, `.env.example`에 있는데 쓰이지 않는 값. 근거(파일과 기호, 돌린 grep)와 위험(없음 / 테스트 필요 / 동작 바뀜)을 같이 받는다.
5. 할 것과 하지 않을 것을 나눈다. 동작·스키마·응답이 바뀌는 것, 사용자가 정한 값은 '묻는 목록'으로 뺀다.

## 2. 소스를 나눈다

- 파일을 통째로 읽기 전에 `python3 docs/outline.py <파일>`로 구성을 본다.
- **컴포넌트가 여럿인 파일**: 하위 컴포넌트를 제 파일로 그대로 옮긴다(Sonnet). 옛 경로를 다시 내보내는 파일을 남기지 않고 import를 고친다.
- **컴포넌트 하나가 큰 파일**: 상태와 effect 묶음을 훅(`src/hooks`)으로, 순수 계산을 `src/lib`로 뺀다(Opus). effect의 순서와 의존 배열, 구독 해제를 그대로 지킨다. 순수 계산을 빼면 `test/`에 테스트를 더한다.
- **수집 스크립트**: 여러 스크립트가 같이 쓰는 것은 `stock-collector/_utils.py`로(Sonnet). 요청 간격과 재시도 값은 바꾸지 않는다.
- 코드는 그대로 옮긴다(주석 포함). 내보내는 이름을 바꾸지 않는다. 새 파일의 머리에 무엇이 들었는지 주석을 단다.
- 서브에이전트에는 고칠 파일, 다른 서브에이전트가 만지는 파일(그 파일은 import 줄만), 읽을 안내, 돌릴 검사를 적어 준다. 전체 검사는 시키지 않는다(메인이 끝에 한 번).

## 3. 문서를 맞춘다

- 새 파일을 그 폴더의 파일 표(`CLAUDE.md`의 `## 파일`)에 올리고 없어진 파일의 줄을 지운다.
- 옮겨진 기호를 옛 파일 이름으로 적은 곳을 고친다(Sonnet). `check-index.py`가 '어디를 볼까' 표는 잡아 준다. 그 밖(`docs/INDEX.md`, 안내의 '지킬 것')은 옛 파일 이름으로 `grep -rn` 한다.
- 폴더 안내가 길면 파일 표를 옆의 `FILES.md`로 뺀다. '지킬 것'은 지우지 않는다. 같은 말이 두 번이면 하나로 합친다.
- 코드와 다른 문서는 코드를 확인하고 문서를 고친다.

## 4. 검사하고 올린다

1. `sh tool/check.sh`. 컴포넌트를 나눴으면 `sh tool/check.sh build`까지, 그리고 개발 서버로 그 화면을 열어 본다(열어 보지 못했으면 보고에 적는다).
2. 웹·수집기·문서로 나눠 커밋한다. push는 [저장소 규칙](../../../CLAUDE.md)의 '검사와 커밋'대로(이메일 확인, 배포 상태 확인).

## 5. 남긴다

- `docs/history/YYMMDD_정리-작업기록.md`를 쓰고(같은 날 기록이 있으면 거기에 더한다) [작업 기록 색인](../../../docs/history/README.md)의 '문서·규칙·도구' 표와 '날짜순'에 올린다. 들어갈 것: 나눈 파일(전·후 줄 수), 고친 것, 하지 않은 것과 이유, 확인 못 한 것.
